Feature Hierarchy 与 Action-Matched Control：如何证明收益来自状态选择

Last materially modified: 2026-08-29

TL;DR：少成交带来的少亏，不等于状态选择创造了价值

问题：一个冷却策略比 baseline 少亏了，但它也减少了成交。怎样判断改善来自“在正确的市场状态采取了动作”，而不只是“整体少做了一点”？

结论：NarrowGate Full-Multiscale 研究同时冻结了两道对照。第一道是 feature hierarchy，也就是按 E1 → E2 → E3 → M2 的顺序逐层证明新增状态信息有增量价值；第二道是 action-matched control，它复制候选策略的动作频率和冷却时长分布，却故意打散“什么状态对应什么动作”。候选相对这类控制的差值，才是状态语义增量的直接诊断。

证据边界：本文只解释 30 日 family-specific historical Development（特定研究族的历史开发集）上的 nested chronological out-of-fold，简称 nested chronological OOF，即嵌套时间序列样本外结果。队列采用同毫秒歧义删失的 modeled replay；它不是 receive-time、严格交易所队列、最终 refit artifact、Validation、sealed holdout 或 live 证据。

状态：BUY 的 E3_HIGHER_ORDER_BOOLEAN 有 +0.458577 USDC/day 的 gross terminal 点估计，也比 action-matched control 多 +0.193888 USDC/day；但语义增量区间跨零，而且 hierarchy 的第一道 E1 vs B0 门没有通过。SELL 没有正的 non-baseline candidate。因此 supported_sides=[]，研究在 Development 关闭，没有 final refit、action 或 live authority。

系列总览见 NarrowGate Full-Multiscale：从多尺度 EMA 到 Boolean Cooldown 的一次阴性研究。项目源码与公开研究边界见 NarrowGateMaker。

1. 先把三个可能混在一起的效应拆开

假设 baseline 一天成交 100 次、亏 10 USDC；某个候选策略只成交 50 次、亏 5 USDC。它的日收益改善是 5 USDC，但平均每次成交并没有变好。这个结果可能只是“把一半生意关掉了”，还不能证明策略能识别坏状态。

对路径依赖的 maker 策略，更完整的分解是：候选改变了多少次动作、选择了哪些冷却时长，以及把这些动作分配给了哪些市场状态。前两项是 action mix，最后一项才是 state selection。

2. Candidate ladder：不是把所有特征扔进一次比赛

Full-Multiscale 没有让所有候选自由竞速后只展示冠军，而是在读取结果前冻结了候选阶梯。

层级 它增加了什么 它要回答的问题
B0_CURRENT_EXACT 实验冻结时逐行复现的 exact owner baseline 当前对照到底是什么
B1_CAMPAIGN_AGE_ONLY campaign age 仅凭持仓过程年龄是否足够
B2_CAMPAIGN_PLUS_H16_H256 16 秒与 256 秒交叉新鲜度 少量预设尺度是否增加价值
B3_CURRENT_SEMANTIC_EQUIVALENT 统一三值与 readiness 语义 语义重写能否忠实复现当前规则
E1_FULL_EMA_BANK 十个 EMA half-life、全部 45 个 fast/slow pair 完整多尺度库是否优于 B0
E2_DIRECTIONAL_EMA cross direction、age、persistence、distance、slope、curvature、convergence、expansion 方向与形状是否在 E1 之上增加价值
E3_HIGHER_ORDER_BOOLEAN 有界的有序 AND/OR/NOT 多规则交互 高阶状态组合是否在 E2 之上增加价值
M2_TRUE_INCREMENTAL 后置 trade、flow 与 depth 状态 成交与深度是否在最佳 EMA 表示之上增加价值
ACTION_MATCHED_CONTROLS 与每个候选匹配 action rate 和 duration distribution 改善是不是仅由动作数量与时长结构造成

3. 为什么需要 Feature Hierarchy

十个 EMA half-life 会形成 $\binom{10}{2}=45$ 个 fast/slow 配对。每个配对又可以产生方向、cross age、persistence、distance、slope、curvature、convergence 与 expansion 等状态，再进入多条 Boolean 规则。即使每个单独候选都没有真实优势，只要尝试足够多，也很容易找到一个历史均值为正的“冠军”。

Nested OOF 通过“只在过去日期中发现规则、在未来 outer fold 中评价”削弱这种偏差；feature hierarchy 则进一步约束解释权限。两者解决不同问题：OOF 防止同一结果直接参与训练，hierarchy 防止研究者在许多信息层中跳过失败层，只展示最漂亮的后层赢家。

6. 为什么 E3 仍不能越级成为 winner

BUY E3 的 gross terminal uplift 为 +0.458577 USDC/day，四个 outer fold 平均值全部为正，20 个 outer-test days 中有 13 日改善，fills 只减少 2.71%。如果研究规则是“挑最终均值最大的候选”，它会显得很强。

但冻结合同问的是一组更严格的问题：E1 相对 B0 是否建立了 full EMA bank 的增量；E2 的方向信息是否再增加价值；E3 的高阶 Boolean interaction 是否再增加价值；候选是否在 simultaneous uncertainty、tail、campaign 与 lifecycle 上都没有不可接受的失败。

第一道 E1 vs B0 hierarchy gate 没通过，E3 的 semantic day interval 也跨零；required tail 与 lifecycle gates 同样失败。因此它的 candidate_class 是 hard_gate_failed，不能获得 ranking、final refit 或 promotion 权限。

这条规则最有价值的地方，是它在结果出来以后仍然约束研究者。否则我们可以先试很多层，再把“E3 赢了”写成完整多尺度状态已被证明；这会把探索性发现误写成确认性证据。

7. SELL 为什么必须单独报告

BUY 与 SELL 的库存方向、对手方 taker flow、修复路径和动作支持不同，不能用 pooled 平均值互相遮盖。SELL E3 相对 exact B0 的 terminal increment 是 -0.009708 USDC/day，fill retention 为 101.18%，20 日中有 12 日改善；但总体点估计仍为负，simultaneous lower bound、tail 与 lifecycle gates 均失败。

因此 BUY 的后层正信号不能替 SELL 补票。这个研究没有 supported side，而不是“BUY 成功、SELL 以后再说”。

8. 正确的阅读方式

Action-matched control 回答的是“同样的动作量与时长组合下，状态分配是否还有增量”；feature hierarchy 回答的是“这个增量能否被归因到预先声明的信息层”；nested chronological OOF 回答的是“过去学习出的规则在未来日期是否复现”。三者缺一不可。

对 BUY E3，最准确的表述是：它给出了一个不能由简单减量完全解释的正 Development 点信号，但这个语义增量尚未排除零，基础 hierarchy 也未建立，所以它是值得保存的 hypothesis，不是获准晋级的策略。

这也是为什么“更聪明的规则”不能只和固定 baseline 比。若没有 action-matched control，我们不知道收益是否来自少做；若没有 hierarchy，我们不知道收益是否来自预先声明的信息层；若没有时间序列 OOF，我们不知道它是否只是历史赢家。
