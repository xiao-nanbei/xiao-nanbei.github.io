Nested Chronological OOF：时间序列策略搜索怎样避免提前看答案

Last materially modified: 2026-08-29

TL;DR：外层回答“算法能否泛化”，内层负责“在过去里选规则”

这篇文章要回答的问题是：当一个做市研究同时搜索指数移动平均（exponential moving average，EMA）配对、Boolean（布尔逻辑）条件、规则复杂度和 cooldown duration 时，怎样避免先看完整历史中的赢家，再把同一段历史包装成“样本外”结果？Cooldown duration 是一次增加同侧库存的成交以后，再次允许同侧加仓前要等待的时间。

NarrowGate Full-Multiscale 使用 nested chronological out-of-fold，中文可称“嵌套时间序列样本外”。30 个按时间排列的历史 Development 日期被切成四个 expanding outer fold：10→5、15→5、20→5、25→5，合计产生 20 个 untouched outer-test days。每个 outer-training block 内再建立三个 expanding inner fold；feature census 与 fold fitting 只能看 inner-train，复杂度和 profile 只能由 outer-train 内部的 inner OOF 选择，外层测试日只能执行已经冻结的 fold policy。

结论边界也必须先说清楚：这套流程给出的是 fold-specific 学习算法的 Development OOF 证据，其中 Development 是研究开发集，OOF 是 out-of-fold（折外样本）。它没有给一个使用全部 30 日 refit 的固定 artifact 提供 OOF 证明，也没有创建 final refit、Validation、sealed holdout、action 或 live authority。Full-Multiscale 最终没有任何 supported side；BUY 的正点信号没有改变这个状态。本文所说的 campaign，是库存进入某一方向以后，直到回到 flat（净库存归零）或到达冻结观察终点的一段完整库存路径。

本文是 Full-Multiscale 总览 的时间序列评价篇。项目源码与公开研究材料见 GitHub - xiao-nanbei/NarrowGateMaker。文中的 value、fill 和 uplift 都属于特定 modeled replay 的历史 Development 研究量，不是收益承诺。

1. 为什么普通随机 K-fold 在这里不成立

标准随机 K-fold 会把样本打乱，再轮流拿一部分做测试。对独立同分布的静态样本，这通常很有用；对 maker 策略路径，它会同时破坏时间方向和状态依赖。

设按日期排序的数据为 $D=(d1,d_2,\ldots,d{30})$，第 $i$ 日的策略状态不仅依赖当天行情，还可能依赖此前的特征归一化、规则选择与 campaign 结构。研究在时刻 $t$ 可使用的信息必须满足：

也就是当前决策只能由严格更早时刻已经可见的变量生成。随机打乱以后，训练集可能包含 $d_{25}$，测试集却包含 $d_8$；模型等于从未来市场状态回头解释过去，这不是一次可执行的历史决策。

第二个问题更隐蔽：同一天的一条训练行可能拥有跨越测试边界的观察终点。例如某次 fill 的 cooldown、后代订单、库存修复或 campaign terminal 一直延伸到下一段。即使 feature timestamp 在训练窗内，它的 label 仍可能包含测试时段的信息。

第三个问题是选择泄漏。假设研究有 $M$ 个候选规则，真实期望都等于零，但先在完整 30 日上取最大值：

只要估计存在噪声，通常就有 $\mathbb E[\max_m\widehat\Delta_m]>0$。这个正数可能只是“从很多噪声里挑最大值”的赢家偏差；随后再用相同日期计算置信区间，并不会把已经发生的选择还原成样本外证据。

3. 每个 outer train 里面为什么还要三个 inner folds

如果只做外层切分，却在 outer-test 上选择 EMA pair、tree depth 或规则条数，外层测试仍然被用于训练。Nested OOF 的核心，是把“选择模型”和“评价选择过程”拆成两层。

对第 $k$ 个 outer fold，研究先只拿到 $T_k$。实现从训练前缀的第 6 个日期开始，把剩余位置按时间顺序分成三个 inner-test block；每个 inner-test block 的训练集都是它之前的前缀。以最短的 10 日 outer train 为例，三组测试大致覆盖第 6–7 日、第 8–9 日和第 10 日，而对应训练前缀依次扩张。

因此，对每个 outer fold，正确顺序是：

  1. 只在 purged outer-train 行上物化 one-shot 训练标签，outer-test 行不得进入标签请求。
  2. 三个 inner fold 分别完成 feature census、support 检查、经济筛选、复杂度比较和候选评价。
  3. 用 inner OOF 结果选择 profile，不读取 outer-test 经济结果。
  4. 在 purged outer train 上 refit 该 fold 的 policy。
  5. 冻结以后，在五个 outer-test days 上运行 repeated sequential full-path replay；不再改 feature、threshold、duration 或复杂度。

这评价的不是一条永远不变的规则，而是一个完整学习程序：如果研究者只拥有当时的历史，这个程序会选出什么 policy，它在接下来的五天表现如何。

4. Purge 与 washout：标签没有越界，才算真正的过去

仅仅要求 train day < test day 还不够。一个训练机会 $i$ 有 assignment time $a_i$、observation end $e_i$ 和 campaign id $g_i$；测试段最早 assignment time 记为 $b_k$，测试 campaign 集合记为 $G_k^{test}$。实现保留训练行的条件是：

如果 $e_i$ 未知、跨过测试边界，或同一 campaign 同时出现在训练与测试中，这条训练行就被移除。这样做不是为了让样本“更干净”，而是为了阻止未来订单、queue、inventory、cooldown 与 campaign terminal 通过 label 倒流进训练。

这也是 purge 与一般日历 embargo 的差别：固定空出一天只是粗糙缓冲，washout-aware purge 直接检查每条机会的观察终点和 campaign 连续性。对路径很短的行，它不会无谓删除大量历史；对跨界的长尾路径，它也不会因为“日期已经换了”就误判为安全。

5. 四种常见的“伪 OOF”

第一种，是在全部 30 日上挑出最强的 45 个 EMA pair 之一，再把选好的 pair 带进四个 outer fold。外层拟合可能没有直接看到测试 label，但 feature universe 已经由未来结果筛过。

第二种，是用 outer-test 结果决定 tree depth、规则数量、阈值、duration 或是否换成连续模型，然后只报告最终赢家。此时 outer test 已经变成第二个 validation set。

第三种，是训练时正确做了 nested split，最终却把 one-shot opportunity effects 相加作为外层 PnL。它解决了时间选择泄漏，却没有解决动作引起的路径变化。

第四种，是在看到 day-level interval 跨零以后改用更有利的 week block、删除坏日或缩小 simultaneous family。Full-Multiscale 的 BUY E3 day band 为 [-0.348400, +1.265554] USDC/day，week-block band 为 [+0.140288, +0.917819]；冻结合同不允许因为后一条更漂亮，就把前一条从 primary gate 中移除。

所以证据链必须分三层：

  • learning_algorithm_fold_specific_policies：本文的 nested OOF 能够回答的层级。
  • final_full_development_refit_artifact：使用全部 Development refit 后产生的固定候选，只证明 artifact 已冻结，不证明它已被独立测试。
  • exact-artifact confirmation：需要在 artifact 冻结之后，用符合新证据合同的数据或另行授权的真实随机实验确认。

把第一层写成第三层，会让“算法在过去多个切点能否重学”与“今天这一个固定策略是否有效”混为一谈。

7. Full-Multiscale 的结果怎样读

BUY 的 E3_HIGHER_ORDER_BOOLEAN（下文简称 E3，即高阶布尔规则候选）在 20 个 outer-test days 上相对实验冻结时的 exact owner baseline 得到 +0.458577 USDC/day terminal uplift，四个 outer fold 的均值都为正，13/20 天改善，fills 从 8,565 变为 8,333，保留 97.29%。这些数字说明 nested OOF 发现了一个值得保留的 Development hypothesis。

但 primary day-level simultaneous interval 跨零，feature hierarchy 第一层失败，tail 与 lifecycle gates 也没有通过。SELL E3 为 -0.009708 USDC/day，没有任何 supported non-baseline candidate。于是 supported_sides=[]，没有 final refit，也没有继续读取 Validation 或 sealed holdout。

这恰好说明 nested OOF 的价值不是“保证找到好策略”，而是给研究者一个不能随意补票的评价边界。它允许发现信号，同时保留“不足以晋级”的正式结论。

8. 公开实现与阅读顺序

建议从以下公开材料继续阅读：

  1. Offline successor Spec：30 日 Development identity、四个 outer folds、inner discovery、权限和停止规则。
  2. Nested chronological OOF implementation：fold validation、washout-aware purge、inner profile selection、outer evaluation 与 evidence-scope 检查。
  3. Formal Development component report：BUY/SELL 聚合 OOF 结果与最终 decision。

结语：真正的测试集，不只是“没有参加 fit”

时间序列策略研究中的测试集必须同时满足三件事：它在时间上位于训练之后，没有通过跨界 label 回流到训练，也没有参与候选选择。只满足第一条，仍可能得到非常精致的泄漏。

Nested chronological OOF 的代价是计算昂贵、每个 fold 可能产生不同策略、最后还不能直接宣称一个 final artifact 已被确认。但这正是它诚实的地方：它把“我找到了一个历史 winner”改写成一个更严格的问题——如果只能使用当时已发生的历史，同一个学习过程是否仍能在未来五天重复产生价值？
