One-Shot 反事实为什么不能相加：路径依赖做市策略的完整回放

Last materially modified: 2026-08-29

TL;DR：局部动作标签能教模型，不能直接充当策略 PnL

这篇文章讨论一个很容易被低估的回测错误：如果我们已经知道每个机会分别改成 79 秒、173 秒或更长 cooldown 的局部反事实，能不能把模型选中的所有局部改善直接相加，得到整条策略的收益？这里 cooldown 是一次增加同侧库存的成交以后，再次允许同侧加仓前的等待期；campaign 是库存进入某一方向以后，直到回到 flat（净库存归零）或到达冻结观察终点的一段完整库存路径。

答案是否定的。One-shot 反事实把每次动作单独插入同一条 baseline 历史；但一项会改变 fill、库存或 cooldown 的动作，通常也会改变后一个机会是否存在。把这些局部差分相加，相当于同时使用多个彼此不兼容的世界。

NarrowGate Full-Multiscale 因而把 one-shot duration labels 限定在 outer-training 内用于规则发现；正式经济评价则让 candidate 与实验冻结时的 exact owner baseline 各自从头到尾运行 repeated sequential full-path replay。两条 arm 使用相同外生市场输入和冻结随机源，但维护独立的 orders、inventory、campaign、cooldown 与 EMA state。

结论边界：本文描述的是 exchange-time、modeled-queue 的 30 日历史 Development 研究，共 3,516 个机会。BUY E3 在 repeated replay 中出现正点信号，但 day-level uncertainty、hierarchy、tail 与 lifecycle gates 没有通过；SELL 没有正的 non-baseline candidate。因此没有 final refit、Validation、sealed holdout、action 或 live authority。

本文是 Full-Multiscale 总览 的反事实回放篇。源码与公开研究材料见 GitHub - xiao-nanbei/NarrowGateMaker。

1. One-shot label 在回答什么

设实验冻结时的 exact owner baseline 简称 B0，它的路径在第 $i$ 个机会到达历史状态 $H_i^{B0}$；动作 $a$ 表示选择一个 cooldown duration。One-shot replay 固定这条 baseline history，只在机会 $i$ 把动作改成 $a$，得到局部 outcome：

这种标签很适合回答“在当前已经发生的状态上，哪个 duration 看起来更好”，也适合训练一个从 multiscale state 到 duration 的 learner。它让不同动作在同一个起点上可比，并且可以把 unsupported action 明确保留为 missing，而不是用零填充。

问题在于，$H_i^{B0}$ 是 baseline 世界的历史。如果 candidate 在更早的机会已经采取不同动作，那么它到达第 $i$ 个时刻时，往往不再处于 $H_i^{B0}$；第 $i$ 个 baseline 机会甚至可能根本不存在。

这个例子里的数字只是为了说明结构，正式研究数值来自完整 paired replay。关键不在于 one-shot 近似误差通常向上还是向下，而在于它的目标量与整条 policy 的目标量不同。

4. Full-Multiscale 怎样分工：one-shot 负责学，repeated 负责判

One-shot 并没有因此变得无用。它仍然承担一个清晰角色：只在每个 outer-training period 内，为训练机会生成 side-specific duration targets，帮助 learner 比较冻结的八档动作。它不能请求 outer-test rows，unsupported target 必须保持 NaN，也不能被当作零收益动作。

对外层评价，研究采用两条独立 arm：

  • control：逐行执行实验冻结时的 exact owner baseline。
  • candidate：只在冻结的 target side 执行 fold policy，另一侧委托给相同 B0 语义。

两条 arm 共享相同 market source、receive/feature-ready clocks 与随机源，避免把输入差异误认为策略差异；但它们的 orders、inventory、campaign、cooldown 和 EMA state 必须彼此独立，不能从另一条 arm 复制执行结果。每次 exposure-increasing fill 都重新调用各自 policy，并把输出 state 连续传给下一段。

5. 为什么两条 arm 不能共享“策略状态”

有些回测表面上运行了 candidate 与 control 两次，却让它们共享库存或 campaign checkpoint。这仍然会把路径压回同一个世界。

如果 candidate 延长 BUY cooldown 并少产生一次 fill，它的库存 $q_t^{candidate}$ 应该与 $q_t^{B0}$ 不同。此后 inventory-aware quote、repair、max exposure、campaign terminal 与下一次 eligible add 都必须基于各自库存计算。把 control 的库存拷给 candidate，会消除动作真正要改变的中介变量；把 candidate checkpoint 拷给 control，则会污染 baseline。

Full-Multiscale 的公开 repeated-policy bridge 因而把 arm state 明确拆成 orders / inventory / campaign / cooldown / ema 五部分，要求 segment 之间 state chain 连续；重启时也必须恢复两条 arm 各自的完整状态。Receipt 会拒绝 one-shot aggregation、fresh start 拼接、跨 arm 执行复制或不连续 state chain。

这并不意味着 modeled replay 已经等同真实交易。它只保证在既定 exchange-time、modeled-queue 证据边界内，candidate 与 B0 的内生路径没有被人为合并。

6. Action-matched control 又在控制什么

即使 repeated replay 得到正 uplift，也可能只是因为 candidate 减少了成交，而不是因为它在正确状态选择了正确 duration。研究因此为高阶候选构造 action-matched control：匹配 candidate 的 action rate 与 duration distribution，但不复制状态到动作的语义映射。

7. One-shot、repeated 与 live 各自能证明什么

One-shot labels 可以证明某个训练时的局部动作比较已被构造，并为有界 learner 提供监督信号；它们不证明完整策略 PnL。

Repeated sequential OOF 可以证明 fold-specific policy 在既定 replay mechanics 和 Development 日期上的路径级表现；它不证明最终 refit artifact，也不证明 receive-time transport、strict exchange queue 或真实订单生命周期。

真实 action 或 live authority 还需要独立的 exact-artifact confirmation、执行 parity、安全门槛和明确授权。Full-Multiscale 在 Development gate 处停止，后面这些层级都没有被创建。

8. 公开实现与阅读顺序

建议继续阅读：

  1. Offline successor Spec：明确 one-shot 只进 outer training、outer test 必须 paired sequential replay。
  2. Repeated-policy replay bridge：两条 arm 的状态身份、连续性、共同外生输入和禁止 one-shot aggregation 的实现合同。
  3. Nested OOF implementation：训练标签请求与外层 repeated evaluator 的分离。
  4. Formal Development component report：BUY E3、matched control、SELL 与 hard-gate 结论。

结语：策略改变的不是一个数，而是后面的世界

One-shot 反事实把复杂问题拆成可训练的局部比较，这一步很有价值；危险发生在研究者忘记了这些比较来自同一条 baseline history，并把它们相加成一条从未真正运行过的策略。

在 maker 系统里，订单、fill、库存、cooldown、queue、campaign 与未来 eligibility 会互相递推。一个动作的经济含义正是它如何改变这条路径。因此，最终 estimand 不能是“所有局部好处的总和”，只能是 candidate 与 baseline 各自完整运行以后，两个可实现世界之间的差。
