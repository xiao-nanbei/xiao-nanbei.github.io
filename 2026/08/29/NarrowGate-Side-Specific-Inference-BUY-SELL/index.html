为什么做市研究不能把 BUY 与 SELL 混在一起

Last materially modified: 2026-08-29

TL;DR：BUY 与 SELL 不是同一机制的正负号副本

这篇文章回答一个看似简单的问题：maker BUY 与 maker SELL 都是在盘口提供流动性，为什么不能把两侧样本放在一起训练、算一个 pooled 平均，再给同一套策略结论？

因为两侧面对的库存变化、主动成交对手方、订单簿位置、cooldown action、baseline 行为和经济风险并不相同。一个 maker BUY fill 是挂在 bid 上的被动买单被 aggressive SELL taker 打中；一个 maker SELL fill 则是挂在 ask 上的被动卖单被 aggressive BUY taker 吃掉。继续 BUY 会增加多头库存，继续 SELL 会增加空头库存。即使同一个指数移动平均（exponential moving average，EMA）condition 在几何上完全对称，它对应的 inventory risk、repair path 和 taker-flow 语义也未必对称。Cooldown 是一次增加同侧库存的成交以后，再次允许同侧加仓前的等待期；campaign 是库存进入某一方向以后，直到回到 flat（净库存归零）或到达冻结观察终点的一段完整库存路径。

NarrowGate Full-Multiscale 因而按 side 分开训练、分开 replay、分开构造 simultaneous intervals 和 hard gates；reducing quote 不变，一侧不能用另一侧的结果“救活”。研究结果正好说明这个必要性：E3_HIGHER_ORDER_BOOLEAN（下文简称 E3，即高阶布尔规则候选）在 BUY 有 +0.458577 USDC/day 的正点信号，在 SELL 却为 -0.009708 USDC/day；两侧最终都没有通过完整 Development gate，supported_sides=[]。

证据边界：这些结论来自 30 日、3,516 opportunities 的 historical Development，使用 exchange-time、modeled-queue 与同毫秒歧义 censor。它不是 final-artifact confirmation，也没有 final refit、Validation、sealed holdout、action 或 live authority。

本文是 Full-Multiscale 总览 的 side-specific inference 篇。项目源码与公开材料见 GitHub - xiao-nanbei/NarrowGateMaker。

1. 先把 maker side 与 taker side 映射正确

交易日志里的 BUY 到底指谁买，是最容易产生方向错误的地方。本文的 side 是 maker order side：

被动 BUY order 位于 bid，卖方主动打入 bid 后它才成交；被动 SELL order 位于 ask，买方主动抬走 ask 后它才成交。因此，当研究 maker BUY 的 fill toxicity 时，直接相关的 counterparty flow 是 aggressive SELL，而不是名称相同的 aggressive BUY。

3. Action 与 baseline 本身就是 side-specific 的

Full-Multiscale 的 action 不是 BUY / HOLD / SELL，而是一次 exposure-increasing fill 后选择 total cooldown duration。BUY 与 SELL 各自有八档冻结动作，并且 baseline 是逐行复现实验冻结时的 exact owner baseline，不是一列独立的固定 85 秒常数。

候选策略对 target side 运行；另一侧继续委托 B0，reducing quote 始终不变。这个设计把问题限定为：只改变 BUY cooldown 时，BUY 侧的 sequential campaign economics 如何；只改变 SELL cooldown 时，SELL 侧如何。

5. BUY 的点信号为什么仍不能授权 BUY

BUY E3 的 terminal value 从 B0 的 -2.904117 USDC/day 改善到 -2.445540 USDC/day，差值为 +0.458577 USDC/day；closed-campaign value 改善 +0.604012 USDC/day。Fills 从 8,565 变为 8,333，保留 97.29%，四个 outer fold 均值全部为正，20 个测试日中 13 日改善。

这组数说明 BUY 侧存在值得保留的 hypothesis，但 primary day-level simultaneous interval 为 [-0.348400, +1.265554] USDC/day，仍覆盖负值。E3 相对 action-matched control 的 semantic increment 为 +0.193888 USDC/day，其 day interval [-0.715169, +1.102945] 同样跨零；feature hierarchy、tail 和 lifecycle gates 也失败。

图 1：BUY 的 week-block interval 较乐观，但预先冻结的 primary day interval 与 semantic day interval 都跨零；side-specific 也不能选择性忽略本侧不利口径。

所以 side-specific 的含义不只是“分别打印两行”。BUY 有自己的 positive point estimate，也必须独立通过自己的不确定性、层级与风险门槛；SELL 失败不能推翻 BUY 的信号，BUY 的信号也不能替它自己跳过 gate。

6. SELL 的 101.18% fill retention 为什么不是好消息

SELL E3 相对 B0 的 terminal increment 为 -0.009708 USDC/day，20 个测试日中 12 日改善，fill retention 为 101.18%。如果只看“活跃度没有下降”，101.18% 似乎比 BUY 的 97.29% 更好。

但 fill retention 只回答成交数量保留了多少，不回答新增成交是否有价值。Candidate 可以产生更多 fills，同时带来更差的 adverse selection、库存时间或 campaign terminal。SELL 的 terminal point increment 已经为负，simultaneous lower bound、tail 与 lifecycle gates 也失败；E1、E2、M2、continuous comparator 与简单 campaign-age candidate 的 terminal point increment 同样为负。

因此 SELL 没有 successor candidate。12/20 正日也不能改写整体结果，因为 daily sign rate 只是稳定性诊断之一，不替代 effect size、simultaneous uncertainty 和风险门槛。

7. Side-specific 应贯穿整条研究链

只在最终报表拆 BUY/SELL 还不够。Side-specific identity 应从最早的 feature construction 一直延伸到最后的 permission：

  1. 信息语义：先冻结 maker/taker mapping，再构造 counterparty_taker_*、away_taker_*、depletion、refill 与 queue features。
  2. 动作语义：BUY 与 SELL 使用各自冻结的 duration vocabulary、exact B0 行为和 target-side evaluator；reducing role 不被 exposure-increasing action 改写。
  3. 学习与选择：feature support、Boolean rule、complexity profile 和 continuous comparator 都在 side 内选择，不能先 pooled selection 再事后拆表。
  4. 完整回放：candidate 只接管目标侧，另一侧执行 B0；两条 replay arm 保留独立 inventory 与 campaign state。
  5. 统计推断：simultaneous family、matched control、fill retention、tail、lifecycle 与 hierarchy gate 都分别报告。
  6. 权限：某侧通过只能支持该侧的下一证据阶段，不能自动授权另一侧，更不能由 pooled positive point estimate 生成统一 live policy。

这套边界也避免另一个常见误解：BUY 与 SELL 的结果不同，并不自动证明某个单边市场规律。它可能来自真实 flow asymmetry，也可能来自 baseline action、机会组成、inventory state 或有限样本。Side separation 让这些差异可被检查，而不是提前给出因果解释。

8. 公开实现与阅读顺序

建议继续阅读：

  1. Offline successor Spec：side-specific ladder、八档动作、paired sequential replay 与权限边界。
  2. Causal multichannel v2 design：maker 可见 trade/depth 状态、aggressive flow 与 side-specific duration 语义。
  3. Repeated-policy replay bridge：target side 执行 candidate、opposite side 委托 B0 的合同。
  4. Nested OOF implementation：拒绝 pooled side、分侧学习、分侧 candidate report 与 scorecard。
  5. Formal Development component report：BUY 与 SELL 的实际聚合结果。

结语：先问“哪一侧”，再问“平均有效吗”

把 BUY 与 SELL 合并，通常会得到一个更平滑、更容易展示的数字；代价是失去策略动作真正作用在哪一类库存路径上的信息。对做市研究来说，这不是报表风格问题，而是 estimand 是否明确的问题。

Full-Multiscale 最终没有 supported side，但两侧到达这个结论的路径并不相同：BUY 有强正点信号却未排除不稳定与风险，SELL 连 non-baseline point candidate 都没有。只有把两侧从 feature、action、replay、statistics 到 permission 全程分开，这个差异才不会被一个看似漂亮的 pooled 平均抹掉。
