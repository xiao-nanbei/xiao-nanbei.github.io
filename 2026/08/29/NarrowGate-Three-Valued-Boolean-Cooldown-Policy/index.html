NarrowGate 三值 Boolean Cooldown：缺失不是 False，规则也不能“补票”

Last materially modified: 2026-08-29

TL;DR：三值是信息状态，八档才是动作空间

“三值 Boolean cooldown”最容易被误解成“策略只有三种动作”。实际恰好相反：三值描述每个条件是 TRUE、FALSE 还是 UNOBSERVED；BUY 与 SELL 的动作仍分别从八个预先冻结的 cooldown duration 中选择。UNOBSERVED 的意思是“现有因果证据无法判断”，不是 FALSE 的委婉说法。

NarrowGate 使用 Kleene 三值逻辑组合 AND、OR 与 NOT，再把多条规则按顺序执行 first match。关键安全语义是：如果一条更早、理应优先拥有该机会的规则为 UNOBSERVED，后面的规则不能趁机“补票”；policy fail closed，回到该行实验冻结时的 exact owner baseline 动作。

本文解释公开实现中的逻辑与有界搜索。最终状态仍只到历史 Development：30 日、3,516 个机会的 nested chronological out-of-fold（嵌套时间序列样本外）研究已经完成，但没有任何 side 通过冻结门槛；没有 final refit、Validation、sealed holdout、action 或 live 权限。这里的 baseline 是实验冻结时的精确对照，不是对当前 live 的描述。

系列总览见 NarrowGate Full-Multiscale：从多尺度 EMA 到 Boolean Cooldown 的一次阴性研究。本文只讨论研究方法和历史证据，不构成任何交易建议。

1. 为什么普通二值逻辑不够用

假设规则要判断“4s/16s EMA 是否刚发生 positive cross”。TRUE 表示条件成立，FALSE 表示看到了足够数据且条件不成立；但在 warmup 尚未完成、source gap、feature stale，或者从观察开始以后根本没有见过一次 cross 时，程序既不能说 TRUE，也不能说 FALSE。第三种状态 UNOBSERVED，记作 $U$，就是为这种情况准备的。

如果把 $U$ 强行编码成 FALSE，取反以后就会得到 TRUE：

于是“没有数据证明发生了 cross”会被改写成“有数据证明没有发生 cross”，甚至触发一个带 NOT 的动作。这不是保守近似，而是凭空制造证据。

正确的否定是：

UNOBSERVED 经过 NOT 以后仍是 UNOBSERVED。缺失不会因为换了一个语法方向就获得信息。

2. Kleene AND / OR 的完整真值表

公开实现使用强 Kleene 三值逻辑。AND 中 FALSE 可以确定整个 conjunction 为 FALSE；若没有 FALSE 但至少一个输入为 UNOBSERVED，结果为 UNOBSERVED；只有全部 TRUE 才是 TRUE。

$A\land B$ $T$ $F$ $U$
$T$ $T$ $F$ $U$
$F$ $F$ $F$ $F$
$U$ $U$ $F$ $U$

OR 正好相反：TRUE 可以确定整个 disjunction 为 TRUE；若没有 TRUE 但至少一个输入为 UNOBSERVED，结果为 UNOBSERVED；只有全部 FALSE 才是 FALSE。

$A\lor B$ $T$ $F$ $U$
$T$ $T$ $T$ $T$
$F$ $T$ $F$ $U$
$U$ $T$ $U$ $U$

也可以把运算规则写成分段式：

例如 $F\land U=F$，因为无论缺失项是什么，已经存在的 FALSE 都足以否定 AND；而 $T\land U=U$，因为缺失项仍可能让结果变成 FALSE。类似地，$T\lor U=T$，但 $F\lor U=U$。

4. Ordered first match：为什么后面的规则不能“补票”

一条 policy 可以有多条有优先级的规则。设 $R_1,R_2,\ldots,R_L$ 依次对应动作 $a_1,a_2,\ldots,a_L$，则真正可选择第 $k$ 条规则的条件是：所有更早规则都明确为 FALSE，而且当前规则明确为 TRUE。

若这个集合不存在，policy 回到基线动作 $a_{B0,s}(x)$：

这里“否则”不仅包括所有规则都为 FALSE，也包括某条更早规则为 UNOBSERVED。原因不是实现偷懒，而是动作所有权不可识别：如果缺失字段补齐以后 $R_1$ 可能变成 TRUE，那么 $R_2$ 本来就不该得到这个机会。

$T$ 任意 $a_1$ 第一条规则已拥有机会
$F$ $T$ $a_2$ 前一条明确不匹配，第二条可接管
$F$ $F$ $a_{B0}$ 没有规则匹配

6. Tree 如何编译成 Boolean rule 而不泄漏缺失状态

有界搜索会为每个非控制 action 在 identified rows 上拟合浅树，再把叶路径编译为 DNF clause。一个容易忽略的陷阱是：树可能用阈值把数值编码 $U=-1$ 与 $F=0,T=1$ 分开。如果直接删掉“必须已观测”这条路径限制，运行时的 UNOBSERVED 就可能误入某个动作叶子。

7. “有界”到底限制了什么

Full-Multiscale 明确不是无限制搜索。每个 purged inner-training fold 最多经济筛选 1,024 个特征；每个 action tree 深度最多 6、最多 32 个叶子；编译后的 policy 最多 7 条有序规则；每条规则最多 16 个 OR clause；每个 clause 最多 6 个 literal。

unknown action target 同样保持 missing。只有某个 duration 与该行 exact control 都可识别时，该 action 的训练 effect 才能进入拟合；复制 unsupported row 或填成中性零，不得改变 feature ranking、policy 或动作。

8. 一个完整决策例子

假设 BUY policy 有两条规则：$R_1$ 选择 223 秒，$R_2$ 选择 79 秒，默认执行逐行 baseline。某个机会的输入是：4s/16s positive ordering 为 TRUE，expanding 因 source gap 为 UNOBSERVED；16s/256s last-cross-positive 为 TRUE。

第一条规则需要前两个条件同时成立，因此 $R_1=T\land U=U$。尽管第二条规则可能单独计算为 TRUE，它也不能被执行，因为 $R_1$ 的所有权尚未明确排除。最终输出 baseline，并记录 predicate-unobserved 的 fallback reason。

若另一个机会中 expanding 明确为 FALSE，则 $R_1=T\land F=F$；此时程序才可以继续到 $R_2$，并在 $R_2=T$ 时输出 79 秒。两行看起来只差一个“缺失与否”，动作权限却完全不同，这正是三值 first-match 存在的理由。

9. 研究状态：逻辑实现可验证，不等于策略获批

公开代码验证了三值运算、DNF、ordered first match、observed-only 叶编译、side-specific vocabulary 与 baseline fallback 的实现语义。历史 Development 的外层 replay 也确实让非控制策略重复作用于完整顺序路径，而不是只做静态规则展示。

但最终没有 side 获得支持。BUY E3 有正点信号，仍因 simultaneous day bound、feature hierarchy、tail 与 lifecycle gates 失败；SELL 没有正的 non-baseline candidate。正确状态是 bounded family 在 Development 关闭，而不是“这套 Boolean 规则已经可以进 live”。
